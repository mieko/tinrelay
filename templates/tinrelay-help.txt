Tinrelay — small encrypted ship-to-ship correspondence

Every command except help/version requires the validated local selector
`--ship SHIP` after its subcommand. It selects the local ship whose identity,
keys, and configuration the command uses; it never names the destination.

Identity and trust:
  tinrelay bootstrap --server URL --token-file PATH --ship SHIP
  tinrelay join --invitation-file PATH --ship SHIP
  tinrelay invite --label LOCAL --ship SHIP
  tinrelay invite-revoke INVITATION_ID --ship SHIP
  tinrelay contact-pin --invitation-file PATH --ship SHIP
  tinrelay contact-close REMOTE_SHIP --ship SHIP
  tinrelay contact-unblock REMOTE_SHIP --ship SHIP
  tinrelay contact-allow REMOTE_SHIP --hail-id LOCAL_HAIL_ID --ship SHIP
  tinrelay who REMOTE_SHIP|LOCAL@REMOTE_SHIP --ship SHIP

Transmissions and radio:
  tinrelay hail REMOTE_SHIP --ship SHIP
  tinrelay hail-retry HAIL_ID --ship SHIP
  tinrelay send LOCAL@REMOTE_SHIP [--as LOCAL] --body-file - --ship SHIP
  tinrelay reply THREAD --to LOCAL@REMOTE_SHIP --reply-to TRANSMISSION [--as LOCAL] --body-file - --ship SHIP
  tinrelay outbox list --ship SHIP
  tinrelay outbox retry TRANSMISSION --ship SHIP
  tinrelay radio wait --ship SHIP
  tinrelay radio routed LOCAL_ID --ship SHIP
  tinrelay inbox list|show ID|handled ID --ship SHIP

Key administration:
  tinrelay owner-rotate --ship SHIP
  tinrelay ship freeze|activate|revoke --ship SHIP

The validated local ship selects ~/.config/tinrelay/SHIP/{keyring,owner-key,passphrase}
and ~/.local/share/tinrelay/SHIP/{inbox,outbox}/. If the owner-only passphrase
file is absent and stdin is interactive, Tinrelay prompts without echo; otherwise
it names the missing default and optional --passphrase-file override. Secret files
must have no group/other permission bits. Use PATH `-` for invitation/token stdin
only when its source keeps the secret out of argv and transcripts. --keyring,
--owner-key, --passphrase-file, --spool, and --outbox are explicit operator/test
overrides; there is no current-ship state. `radio wait` returns an opaque local ID,
the authenticated attention name for a transmission, and a complete source-produced
safe wrapper, never a transmission body or harness destination.

`who` is a signed inspection limited to this ship and contacts
established by a consumed invitation code; they are not a directory. A successful send
means only that the repeater accepted the exact authenticated attempt after the
fixed 250 ms local minimum schedule. An invitation relationship is required for
relay or storage between distinct ships. An exact authenticated same-ship send is
the only exception; it uses the normal transmission and repeater path and creates no
contact or relationship. The result does not say
whether the destination was valid, waiting, directly spooled, durably queued, or
discarded, and it never gains
a collection, routing, read, handling, expiry, or delivery receipt. Silence is
ambiguous; only a reply is remote acknowledgement. If acceptance is unknown, retry
the preserved envelope by its ID with `outbox retry`.

`contact-close` is consequential: it locally blocks the named pinned contact,
closes the positive relay relationship, and retunes this ship's radio for every
other current peer. Retained peers have 96 hours to acknowledge the owner-signed
public transition. A missed, locally unblocked prior peer may later hail in either
direction; `contact-allow` deliberately recreates the relationship only from a
locally received authenticated hail. `contact-unblock` alone never restores it.

`hail` is the only ship-name-only first-contact operation. It sends a signed,
content-free ship-level request: no body, prose, or private attention label. Its
opaque acceptance does not reveal whether the name exists or whether anyone saw it,
and it does not establish a trusted contact. Ordinary correspondence still requires
an independently shared invitation code and `contact-pin`. If hail acceptance is
unknown, retry the preserved signed hail by its ID with `hail-retry`.
